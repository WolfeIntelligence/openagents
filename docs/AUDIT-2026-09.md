# OpenAgents functionality audit — September 2026

Audited 2026-09-10 against production (`https://openagents-nu.vercel.app`, commit `281e6ea`) and a
local checkout in both zero-env and DB modes. Scope: what the product should do better or is
missing, not code style. Production was treated as read-only (no sign-in, no purchases, no
publishes; a handful of tarball downloads bumped `openagents/pr-reviewer`'s counter).

Method: browser walk-through of every page at desktop and 375px, `curl` against every
`/api/*` route, every CLI command against production, a code read of the payments, auth,
publish, catalog and stats paths, and zero-env `next build` / `eslint` / `tsc` /
`check:catalog` locally. Everything passed cleanly on the ops side: the build is green with
zero env vars, there are no 500s on any route in either mode, path traversal is blocked, and
invalid query params degrade safely.

Severity: **blocker** (breaks the core promise or loses money) · **major** (a user hits it
and is misled or blocked) · **minor** (rough edge) · **idea** (would be expected of a mature
marketplace). Effort: S (< 1 hour), M (half a day), L (multi-day).

## 1. Bugs

### B1 · blocker · The CLI is not on npm
- **Where:** landing page install box (`src/app/page.tsx:11`), every `InstallBox`, README, every docs page; `cli/package.json:2` (`"name": "openagents"`).
- **Repro:** `npm view openagents version` → `404 Not Found`. `npx openagents add openagents/pr-reviewer` in a fresh directory fails.
- **Expected vs actual:** The primary call to action on every page should work. It cannot for anyone outside this repo.
- **Fix:** Publish `cli/` to npm under `openagents` (name is unclaimed) or a scoped name, and add a CI job that publishes on tag. Until then, change the install boxes to `npx github:WolfeIntelligence/openagents#cli` or an explicit `npm i -g` from the repo. **Effort: S.**

### B2 · blocker · Paywall bypass through the file viewer
- **Where:** `src/app/api/v1/packages/[owner]/[name]/files/[...path]/route.ts:8-25` and `src/app/p/[owner]/[name]/files/[...path]/page.tsx:18-24`. Neither calls `auth()` or `hasPurchased()`; the download route does (`download/route.ts:25-34`).
- **Repro (live):** `curl https://openagents-nu.vercel.app/api/v1/packages/zwolfe42/paid-release-notes/files/WORKFLOW.md` → 200 with the full paid content. Same for the `/p/.../files/WORKFLOW.md` page. `/download` correctly returns 402.
- **Fix:** Extract the gate from the download route into a `canAccessPackage(pkg, session)` helper and apply it in the raw-file route, the file-viewer page, and the tarball route. Decide which files are previewable for paid packages (README and `openagent.yaml` only) and show a locked state in the Files tab. **Effort: S.**

### B3 · blocker · Purchases can be duplicated, double-recorded, and never refunded
- **B3a Duplicate checkout.** `src/app/api/checkout/route.ts:9-49` never calls `hasPurchased`; a second Buy (stale tab, direct POST) creates a new Checkout session and charges again. Also allows a seller to buy their own package. **Fix:** check `hasPurchased` and `isOwner` before creating the session, return 400. **S.**
- **B3b Non-idempotent webhook.** `src/app/api/webhooks/stripe/route.ts:66-83` inserts a purchase on every `checkout.session.completed`; Stripe retries and manual resends create duplicate rows. `purchases.stripeSessionId` has no unique index (`src/lib/db/schema.ts:134-147`). **Fix:** unique index on `stripeSessionId` + `onConflictDoNothing()`. **S.**
- **B3c Refunds and disputes are ignored.** No handler for `charge.refunded` / `charge.dispute.*`; `status: "refunded"` is documented in the schema comment but never written; `hasPurchased` only checks `paid`, so refunded buyers keep access forever and `/settings/payouts` keeps counting the sale. **Fix:** handle those events, look up by `stripePaymentIntent`, flip status; treat `refunded` as not owned. **M.**
- **B3d Success-page race.** `src/app/p/[owner]/[name]/page.tsx:113-117` shows "Purchase complete — you own this package" purely from `?checkout=success` (anyone can type it) while the Download button still says Buy until the webhook lands. **Fix:** verify the session id server-side (`?session_id={CHECKOUT_SESSION_ID}` in `success_url`) and record the purchase from the success redirect as a fallback to the webhook. **S/M.**
- **B3e Purchase currency not stored.** `purchases` has `amountCents` but no `currency`; `/purchases` and `/settings/payouts` display the package's *current* currency and sum mixed currencies into one total. **Fix:** add `purchases.currency`, group totals. **S/M.**

### B4 · blocker · Subscriptions are fake
- **Where:** `src/lib/manifest.ts:27` and `src/lib/types.ts:16` accept `subscription`; `src/lib/stripe.ts:76` hard-codes `mode: "payment"`; no `customer.subscription.*` handling; no expiry column; `src/app/pricing/page.tsx:102` advertises "One-time or subscription pricing".
- **Repro:** publish with `pricing.model: subscription`, buyer clicks Buy, gets a single permanent charge.
- **Fix:** short term, reject `subscription` at publish and hide it from the pricing page (**S**). Long term, `mode: "subscription"` with a recurring price, `purchases.expiresAt`, and subscription webhooks (**L**).

### B5 · major · Installed packages are invisible to the runtimes they target
- **Where:** `cli/lib/runtimes.js:130-147` installs every kind into `.claude/skills/<name>/` and `.cursor/rules/<name>/`; no seed `SKILL.md` has YAML frontmatter (`head -1 catalog/openagents/*/SKILL.md` finds none); workflows/harnesses/rules install as `WORKFLOW.md`/`HARNESS.md`/`RULES.md` with no `SKILL.md` at all. Claude Code discovers skills only via `SKILL.md` with `name`/`description` frontmatter; Cursor discovers rules only via top-level `.mdc` files with frontmatter. The landing page says "Claude Code, Cursor, Codex, and other agent runtimes pick it up automatically" (`src/app/page.tsx:22-25`).
- **Repro:** `openagents add openagents/pr-reviewer --runtime claude-code`, open Claude Code, the skill is not listed.
- **Fix:** In the CLI (and optionally the tarball) generate a runtime shim on install: for `claude-code`, write `SKILL.md` with frontmatter (`name`, `description` from the manifest) that points at `entry` (or rename the entry file when it *is* `SKILL.md` and add frontmatter); for `cursor`, write `.cursor/rules/<name>.mdc` with `description`/`globs`/`alwaysApply` frontmatter wrapping `entry`; for `rules` kind also offer an `AGENTS.md`/`CLAUDE.md` include line. Fix `src/lib/runtimes.ts:29-40` which disagrees with the CLI and docs on `openai-agents` (`agents/` vs `.openai-agents/`) and `langgraph`. **Effort: M.**

### B6 · major · Versioning and review are not enforced
- **B6a** `src/lib/publish.ts:117-125` inserts a `package_versions` row on every publish with no `(packageId, version)` uniqueness; republishing 1.0.0 twice yields two "v1.0.0" entries (and a React duplicate-key warning in `VersionsTab`). **Fix:** unique index + 409 on duplicate. **S.**
- **B6b** `latestVersion` is overwritten unconditionally (`publish.ts:92,104-115`); publishing 0.9.0 after 1.2.0 makes 0.9.0 the served version. **Fix:** compare semver, require strictly greater (or explicit `--allow-downgrade`). **S.**
- **B6c** Docs promise a review queue and `status: "pending_review"` (`src/content/docs/publishing.md:63-84`, `api.md:167-170`) and the form says the package "should now appear once it finishes processing" (`src/components/PublishForm.tsx:90-93`). There is no `status` column; packages are live and purchasable the instant they are inserted. **Fix:** either add `packages.status` (`pending|live|rejected|deprecated`) with an owner-only preview and an admin allowlist, or correct the docs and form copy now. **S (docs) / M (status column).**
- **B6d** `package_versions.changelog` exists and renders but nothing ever writes it. **Fix:** accept `CHANGELOG.md` or a `changelog` field in the publish body. **S.**

### B7 · major · Wrong canonical domain everywhere
- **Where:** `src/app/layout.tsx:24` (`metadataBase: new URL("https://openagents.dev")`), `src/app/sitemap.ts:5`, `src/app/robots.ts:10`.
- **Repro (live):** `curl https://openagents-nu.vercel.app/robots.txt` → `Sitemap: https://openagents.dev/sitemap.xml`; `curl https://openagents.dev` → no response. Every `og:image` URL a social card would fetch is on the dead domain; no `<link rel="canonical">` is emitted.
- **Fix:** one `siteUrl()` helper reading `NEXT_PUBLIC_SITE_URL`, then `VERCEL_PROJECT_PRODUCTION_URL`, then `http://localhost:3000`; use it in layout metadata, sitemap, robots, checkout/onboard `siteUrl`. Add `alternates.canonical` per page. **Effort: S.**

### B8 · major · Seed package dates are fake for 17 packages
- **Where:** `catalog/openagents/*/` — only 11 of 28 have `.meta.json`; `src/lib/catalog/seed.ts:143-150` falls back to `BUILD_TIME` on Vercel because bundled mtimes are normalized.
- **Repro (live):** `/api/v1/packages?sort=updated` shows 17 packages "updated 2026-09-10" (today's deploy) and they will move to every future deploy date. None of them can be featured.
- **Fix:** run `npm run sync:meta` and commit; add a `.meta.json`-presence check to `scripts/check-catalog.ts` so CI catches it next time (see G-Ops). **Effort: S.**

### B9 · major · Search quality and contract
- **B9a** DB search only matches `title`/`summary`/`name` (`src/lib/catalog/db.ts:132-141`) while seed search also matches `owner` and `tags` (`seed.ts:231-241`). Live: `?q=changelog` misses `zwolfe42/paid-release-notes` whose tag is `changelog`. **Fix:** add owner and a tags clause (`EXISTS (SELECT 1 FROM jsonb_array_elements_text(tags) t WHERE t ILIKE …)`). **S.**
- **B9b** `%`/`_` in `q` are unescaped LIKE wildcards in DB mode (`db.ts:133`); `?q=_` matches every DB package. **Fix:** escape `\`, `%`, `_`. **S.**
- **B9c** Multi-word queries are one substring match; `"code review"` finds nothing although the docs' own example uses it (`api.md:99`). **Fix:** tokenize on whitespace, AND the terms across title/summary/name/tags; rank name/title hits first. **M.**
- **B9d** `GET /api/v1/search` returns 200 on missing `q` and omits `total`; docs promise 400 and `total` (`src/app/api/v1/search/route.ts:9-12`). **Fix:** validate and return `{items, total}`. **S.**
- **B9e** Default page size differs by mode: seed 24, DB "everything", `withStats` 24 for downloads/stars sorts (`db.ts:195`, `index.ts:108`). Live: `/api/v1/packages` returns 29/29 items, `?sort=downloads` returns 24/29. **Fix:** default `limit` once in `parseCatalogQuery` (24, max 100) and document it. **S.**

### B10 · major · Download counter is inflatable
- **Where:** `src/app/api/v1/packages/[owner]/[name]/download/route.ts:42` counts inside `GET`, which Next also invokes for `HEAD`; owners and bots count; no rate limiting on any route (35 rapid requests, no 429).
- **Repro (live):** counter went 10 → 13 after two GETs and one HEAD.
- **Fix:** add an explicit `HEAD` handler that skips `recordDownload`; skip owner downloads; dedupe by hashed IP + package per hour in `package_stats` or a small `download_events` table (which also enables the analytics in G-Stats). Add per-IP rate limiting on download, star, checkout and publish (Vercel WAF rules or an Upstash token bucket). **Effort: S (HEAD/owner) / M (dedupe + limits).**

### B11 · major · Mobile navigation is missing
- **Where:** `src/components/Header.tsx:28` hides `NavLinks` below `md:` with no menu; `src/app/explore/page.tsx:505` renders the filter sidebar (1408px tall at 375px) above results.
- **Repro:** at 375px the header has only logo, search and Sign in; Explore requires ~1.7 screens of scrolling before the first package.
- **Fix:** hamburger drawer for nav; on Explore, collapse filters into a "Filters" disclosure or a horizontal chip row below `lg:`. **Effort: M.**

### B12 · major · Identity edge cases
- **B12a Seed-owner collision.** A GitHub user whose login is `openagents` gets handle `openagents` (`src/lib/auth.ts:151-158`) and can publish `openagents/pr-reviewer`, which replaces the seed package everywhere because DB wins on id conflicts (`db.ts:153-158,199-210`). **Fix:** reserve every `catalog/<owner>` directory name and a small blocklist (`admin`, `api`, `docs`…) in handle derivation and in `publishPackage`. **S.**
- **B12b Handle rename orphans packages.** Handle is rewritten on every sign-in; `packages.owner` is plain text; a renamed GitHub user can never update their old packages and `/u/<old>` keeps showing them. **Fix:** store `packages.userId`, treat `owner` as a display slug, and migrate `owner` on rename (or refuse rename while packages exist). **M.**
- **B12c** `Header.tsx:41` links `/u/<display name>` when `handle` is undefined. **S.**

### B13 · major · CLI correctness
- **B13a** `-v`/`--version` is intercepted globally (`cli/bin/openagents.js:50`), so `openagents init --version 2.3.1` writes `version: true` into the manifest. **Fix:** only treat `--version` as the global flag when it is the command. **S.**
- **B13b** The hand-written YAML parser (`cli/lib/yaml.js`) silently mangles block scalars (`|`, `>`), drops the keys after them, accepts `key: a: b` that the server's `yaml` rejects, and flattens tab indentation. `openagents validate` can pass locally and the server can reject the same file, or worse, the CLI shows the wrong tags. **Fix:** either vendor a tiny real YAML subset parser or throw on `|`, `>`, tabs and nested colons with "unsupported, quote the value". **M.**
- **B13c** `add` on a paid package prints `download failed: HTTP 402` and discards the server's `{"error": "purchase required…"}`; `fetchJson` leaks raw HTML bodies on other errors (`cli/lib/commands/add.js:66-70`, `cli/lib/util.js`). **Fix:** parse and surface `error`, point the user at the package URL to buy. **S.**
- **B13d** `entry:` line ignores `--dir` (`add.js:96-98`); `publish` prints a doubled URL (`cli/lib/commands/publish.js:11`); unknown flags are silently ignored; bare `openagents` exits 0. **S each.**

### B14 · minor · API surface consistency
- `/api/v1/publish`, `/api/checkout`, `/api/connect/onboard` bypass `src/lib/api.ts` so they have no CORS headers and no `OPTIONS` (`publish/route.ts:1-47`). **S.**
- Unmatched `/api/v1/*` paths (e.g. `/api/v1/packages/openagents`) return the HTML 404 page, not `{error}`; add `src/app/api/v1/[...rest]/route.ts`. **S.**
- `files/{path}` always returns `text/plain` even for `.json`/`.yaml`. **S.**
- `catalog.list` in DB mode has no try/catch, so a DB blip 500s `/explore` while `getStats` swallows errors; `hasPurchased` likewise. Wrap both, fail to seed / not-owned. **S.**
- `star` `GET` loads the full package (files, readme) just to check existence. **S.**
- `account.updated` v1 branch (`webhooks/stripe/route.ts:85-94`) will write `stripeOnboarded: false` if Stripe ever sends it for a v2 account. Guard or remove. **S.**

### B15 · minor · Page-level rough edges
- `/explore?page=999` shows "No packages match those filters" with no way back except "Clear filters" (`explore/page.tsx:606-618`); clamp `page` to the last page. **S.**
- Two `<h1>` per package page: the README's `#` title renders as a second h1 (`src/components/Markdown.tsx`); shift README headings down one level. **S.**
- `--fg-subtle: #71717a` measures ~4.1:1, below WCAG AA 4.5:1 (`src/app/globals.css:17`). **S.**
- Relative links and images inside READMEs are not rewritten (`Markdown.tsx` has no `urlTransform`), so `./diagram.png` 404s; map to `/api/v1/packages/{owner}/{name}/files/…`. **S.**
- `openagent.yaml` is servable but not linked from the Files or Manifest tab. **S.**
- Pricing hero still says paid packages "will carry" a fee though payments are live (`src/app/pricing/page.tsx:60-61`); `getting-started.md` says "Ten packages ship free" (28); README and SPEC say GitHub-only auth and Express accounts. **S.**
- The only paid package on the public storefront is a test package whose summary says "(test paid package)". Unlist or replace it. **S.**

## 3. Product gaps a Hugging Face-style user expects

Grouped by the themes requested. Effort is for a solid first version.

### Versioning and changelogs
- **G-V1** Real version history: list every published version with date, changelog, file list, and a per-version download/install (`@version`). Immutable versions once published. **M**
- **G-V2** Changelog input on publish (`CHANGELOG.md` or a field) and rendering in the Versions tab; "What's new" on the card when updated in the last 30 days. **S**
- **G-V3** Dependency resolution for `requires` in the CLI with a lockfile (`.openagents/lock.json`) recording name, version, integrity hash, runtime and install path. Enables `openagents list`, `remove`, `update`, `outdated`. **M–L**
- **G-V4** Tarball integrity: `ETag`/`sha256` on download, verified by the CLI; `Cache-Control: immutable` for versioned tarballs and raw files. **S–M**

### Package search quality
- **G-S1** Tokenized, ranked search across name, title, summary, tags, owner, README (Postgres `tsvector` with `websearch_to_tsquery`, or `pg_trgm` for typo tolerance) with the same behaviour in seed and DB modes. **M**
- **G-S2** Search-as-you-type suggestions in the header (`/api/v1/search` already returns 10). **S**
- **G-S3** Facet counts on Explore (how many packages per kind/runtime/price for the current query), "clear all", and a visible chip row of active filters. **M**
- **G-S4** Sort by "trending" (downloads in last 7 days) once download events exist. **M**

### Categories and discovery
- **G-C1** A tag index page (`/tags`) and canonical category taxonomy (e.g. code-review, testing, security, docs, data, ops) with curated landing pages; tags today are free-form and only appear as chips. **M**
- **G-C2** "More from this creator" and "Similar packages" (shared tags/kind) on the detail page; "Recently updated" and "Most installed" rails on the landing page. **S–M**
- **G-C3** Collections/lists ("Starter kit for Claude Code") curated by staff or users. **L**
- **G-C4** Folder grouping in the Files tab, README table of contents with heading anchors, syntax highlighting in the file viewer. **S–M**

### Reviews and ratings
- **G-R1** Stars exist; add a "Starred by me" page (`/stars`) and a star count on cards (already shown). **S**
- **G-R2** Reviews with a 1–5 rating and text, verified-purchase badge for paid packages, sort by rating, seller reply. Requires moderation (see below). **L**
- **G-R3** Lightweight "Did this work for you?" thumbs on the package page as a step before full reviews. **M**

### Seller profiles and org ownership
- **G-P1** Profile settings page: display name, bio (`users.bio` exists but is never written), avatar, website, GitHub link, and the ability to choose a handle once (with reserved-name rules, B12a). **S–M**
- **G-P2** Creator page: join date, total stars/downloads across packages, sort and pagination, "verified" badge for GitHub-linked orgs. **M**
- **G-P3** Organisations/teams: an `orgs` table with members and roles; `packages.owner` can be a user or an org; publishing requires membership; transfers between owners. Unblocks the seed `openagents` owner being a real org. **L**
- **G-P4** Account deletion with package handling (transfer or deprecate first). **M**

### Install analytics
- **G-A1** Record download events (package, version, runtime from a CLI header, hashed IP, day) instead of a bare counter; show sellers installs over time, by version and by runtime on `/settings/payouts` (or a new `/dashboard`). Public sparkline on the package page. **M**
- **G-A2** Page views per package (server-side counter or Vercel Analytics custom events). **S**
- **G-A3** CLI sends `User-Agent: openagents-cli/<version> (<runtime>)` and a `?runtime=` hint on download so analytics can attribute installs. **S**

### Moderation and reporting
- **G-M1** "Report this package" button (prompt-injection, malware, license, spam) writing to a `reports` table with an email notification. **S–M**
- **G-M2** Admin role (`users.isAdmin` or an env allowlist) with a minimal `/admin` page: pending queue, approve/reject with reason, feature/unfeature, unlist, takedown, and suspend user. Replaces today's SQL-only featured management. **M–L**
- **G-M3** Automated pre-publish checks: secret scanning (regex for keys), size limits, binary rejection, and a prompt-injection heuristic on instruction files. **M**

### License display
- **G-L1** Show the license prominently in the header and card with a link to the SPDX text; validate `license` against the SPDX list at publish (`manifest.ts:44` accepts any string); require `proprietary` for paid packages and forbid it for seed. **S**
